# 5. The tool is called detent

**Status:** Accepted
**Date:** 2026-08-13

## Context

The project was scaffolded as `mcpc`. That name is descriptive but flat, it locks
the tool to a protocol that may be superseded, and it says nothing about what the
tool does. The plan also flagged trademark collision as a low-probability,
high-cost risk to be resolved before the first release rather than after.

Nothing has been published: no release, no NuGet package, no npm package. This is
the cheapest moment this decision will ever be.

## Decision

The tool is **detent**. The binary is `detent`, packages are `detent`, and the
configuration directory is `.detent/`.

A detent is the spring-loaded catch that holds a mechanism in a chosen position
until deliberate force moves it. It is not a lock: it does not prevent the change,
it prevents the change from happening *silently*. That is precisely the product.

## Screening

A good-faith availability screen, not a legal clearance. Screened 2026-08-13:

| Check | Result |
|---|---|
| npm | available |
| NuGet | available |
| PyPI | taken (unrelated, not a channel we ship on) |
| GitHub, name search | nothing above 20 stars, all unrelated |
| USPTO, software classes 9 and 42 | no mark found |

Rejected candidates and why, recorded so they are not re-litigated:

- **plimsoll** - Plimsoll Productions filed in class 009 (computer and software
  products) on 2026-06-26, a direct hit. Also means "gym shoe" in British English.
- **barbican** - collides with OpenStack Barbican, a secrets manager, which is
  adjacent infrastructure and therefore the worst kind of collision.
- **ward** - Warden (2.5k stars), Ward (2.3k), Warden Protocol (2.1k).
- **tally**, **signet**, **lodestar**, **touchstone**, **cachet** - each collides
  with a well-known company or dev tool (Tally Solutions, Signet Jewelers,
  ChainSafe Lodestar, Touchstone/Disney, CachetHQ).
- **indenture** - the better metaphor, a contract torn in two whose halves must
  match, and clean on every registry. Rejected on ergonomics: nine characters in
  every CI file, and "indentured servitude" is an unpleasant echo for a public
  project.

## Relationship to `mcplock`

`detent` is the successor to `mcplock`, per the project plan's Option A (§2):
archived, not a parallel sibling project. There is one lineage to carry
forward and one codebase to maintain, not two audiences to split attention
across. Stated in the README rather than only here, per the plan's own
instruction to decide this on day one and write it down where a reader of the
project, not just its history, will see it.

## Consequences

Finding IDs keep the `MCPC` prefix. It stands for MCP Contract and names the
subject of analysis rather than the tool, so it survives this rename and any
future one. See `docs/arch/diff-rules.md` §3.

`detent` is free on npm, so the Phase 4 npm shim does not need a scope.

This is not legal clearance. Before the first tagged release, a formal search in
the jurisdictions that matter is worth the fee, as the plan's own risk register
says. The screen above lowers the odds of an expensive surprise; it does not
eliminate them.

That re-check is tracked as a blocking gate in `docs/release-checklist.md` rather
than left in this ADR, because an ADR records what was decided and nobody reads
one again at release time.

## Addendum, 2026-08-15: a live competing use found on re-screen

A deeper pass turned up `detentapp.com`, a source-available trading-discipline
enforcement tool trading under the name "Detent" - live, currently at a
waitlist stage. No trademark registration was found for it in this pass, and
every other "detent" hit in a trademark database is firearm-parts trademarks
using the word descriptively (a "detent mechanism," a "detent pin"), not as a
software brand, so those are not real conflicts.

This one is different in kind from the near-misses already recorded above: it
is another *software* product using the identical name, not merely a
same-word collision in an unrelated field. It is not treated as disqualifying
here, for three reasons: no registration was found to be blocked by; consumer
confusion, the actual legal standard, is unlikely between a personal
trading-risk tool and a developer CI gate - different goods, different
channels, different buyers; and it is small and early-stage, which bears on
how much reputation or common-law strength it has accrued so far, though that
can change.

It is exactly the kind of fact a professional clearance search needs to weigh
that this ADR's own screen could not - common-law use is not something a web
search screen reliably surfaces at all, and it did not surface this one until
searched for a second time with different terms. The release-checklist gate
is unchanged in kind, but this finding raises its priority: flag this specific
product to whoever performs the formal search, rather than treating the 2026-08-13
screen as still current.
